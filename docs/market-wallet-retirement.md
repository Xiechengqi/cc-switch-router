# 市场支付清理与验收契约

当前市场只有平台钱包支付，不按 Provider 分户。官方 DujiaoPay 充值模式只决定是否开放新的网关充值；已有余额消费、转账、C2C 与成熟收益自动到账使用各自开关及安全规则。

## 已移除功能

商家专属充值、Binance 凭据与自动到账、授信、预存账户、旧账单及付款声明、旧月租模块、商家支付方式与收款图片资产、旧账务页和收款资料页、Provider 私有资金汇总、外部提现及手动收益转入均不再提供运行模块或 API。Provider 设置保留收入、商品准入与业务联系方式。

独立 `/v1/market/config` 提供汇率及其来源、新鲜度，不依赖支付渠道。

## 资金与服务不变量

- 报价绑定买家、商品及版本。付费提交只接受当前平台钱包报价，竞争或过期必须重新报价，不能改走商家直付。
- 提交冻结，服务确认开通后扣款。不确定的授权失败或 Host 清理不能释放 hold；清理确认后幂等结算与释放。
- 取消已付款月租只关闭续费，保留到期前服务；试用、按秒及暂停服务可立即发起清理。
- 未履约返还属于服务结算，只回平台余额，不是现金退款。
- Provider 按冻结费率分账，净收益沉淀七天后自动入同一余额；不能绕过冻结、争议、身份和对账门槛。
- Share 试用期也提供买家私有生命周期；公开 catalog 不返回钱包合同、余额或争议信息。
- Host 消费合计月度付款与按秒扣费批次，扣除未履约返还；履约分账不重复计入消费。

## 数据及升级边界

已发布基线和迁移保持原校验和。旧金融表保留历史证据，不启动旧 worker、写入旧账户或自动转换资金。本次不删除订单、收据或 journal。

迁移 87 只将存在用户的业务 contacts 复制到独立表，不复制收款方式、支付凭据或资金。部署前备份数据库及独立密钥；本次不提供旧资金合同继续运行或存量资金迁移。

## 验收

Rust 执行 `market_`、`share_market::tests`、`client_market::tests` 及真实 schema migrations；单独的 `market_` 筛选不能覆盖两种租用的完整测试。前端执行 Share / Client / Provider / 钱包单测、类型检查、构建与契约审计。浏览器仅使用本地 mock、DOM 和交互，不截图、不真实付款。

本地测试不能替代 DujiaoPay 真实商户验收；本次不修改远程部署、渠道状态或真实资金。

# Share Market 立即退租与平台余额返还

状态：当前实现。适用于 Share Market，不改变 Client Market 的独立规则。“返还”仅指原租金退回用户的平台余额，不提供外部退款、提现、充值退款或资金二次邮箱验证。

## 用户和处理入口

- “到期不续租”保留已支付周期的服务；“立即退租”停止原车位访问、续租及后续计费。关闭续租后仍可立即退租。
- 租客在市场当前租约或“账号 → 我的租用 → Share 市场”预览、确认和查看结算；预览有效两分钟。确认后保留弹窗，明确区分撤权／最终用量待确认、财务待核对、补偿争议和完成。
- Provider 仅在需要正式处理时，在原 Share 卡片／车位行看到红色“退租处理”；Router 财务 Owner 仅在争议升级后看到红色“退租裁决”。不加顶部待办，不为无待办的每行添加历史按钮。
- 车位再次出租或转交后，旧事项仍绑定原租客、原 Provider、原 entitlement 和 installation。新租客或新 Provider 不因此获得旧事项权限。已下架的事项可通过站内通知 `/share-market/?terminationId=...` 和租客历史进入。
- 详情只向双方及 Router 财务 Owner 开放。普通管理员不获得财务裁决权，当事人即使同时是 Router owner 也不能裁决自己的交易。

## 规则与结算金额

新报价冻结补偿比例，依次复制到合约和付费周期。默认 **10%**，Router owner 可在“设置 → 市场 → 平台钱包”的独立 Share 规则中修改，范围 0–100%，支持两位小数。自动续租保留原合约已接受的比例；新全局规则须通过新报价接受。

历史付费周期不追溯附加补偿或额度折算条款，继续原到期取消规则。新入口还要求 Server 的权威归档覆盖当前付费周期；累计额度要求覆盖首次付费起点。不把旧数据缺失当作零消费，也不虚构历史归档起点。

定义：

- `P`：完整周期已付租金，不含充值维护费。
- `T`：计费截止前，按既有服务证据结算的时长交付租金。
- `Q`：本周期额度消耗折算的交付租金。
- `B`：此前因未交付服务已经退回的本周期租金。
- `A = min(max(Q - T, 0), P - T - B)`：额度交付补差。
- `R = P - T - B - A`：剩余已付租金。
- `C = min(R, round(P × 补偿比例))`：补偿上限。

主动退出：返还 `R - C`，`C` 全额归 Provider。Provider／平台问题：撤权确认后先返还 `R - C`，仅冻结 `C` 等待处理。不能追加扣用户其他余额、不能产生欠款、不能追回之前已返还的钱。

时长与额度取高，不相加。例如月租 $100，已交付 25% 时长，但已消耗 60% 的本周期额度：时长租金 $25、额度补差 $35、剩余 $40。10% 补偿最多 $10，主动退租返还 $30；问题退租先返还 $30，再处理 $10。

### 不同额度周期

- 不限额度：只按时长交付租金。
- 日／周／自然月／锚定 7 天或 30 天：按真实执行窗口计算整段付费周期的标准化额度预算，`预算 = Σ(窗口额度 × 付费周期与该窗口的重叠时长 / 窗口完整时长)`。不能把一天额度用完误算成整月租金全部交付。
- 累计额度：分母为当前付费周期开始时仍剩余的累计额度，须扣除该 entitlement 在此前付费周期已使用的额度。试用请求不计入正式付费消费。
- Token 模式用持久化的真实 Token 数量；美元等值模式仅用 Server 执行价目账本中已结算的 picos，不用 Router 展示估价、不按管理员当前价格重算、不把显示为 $0 或缺失价格当作零使用。
- 金额使用整数账本单位（1 美元 = 8,640,000 units），不先舍入到美分；USD 额度和用量是独立的 micros/picos，不是用户钱包余额。额度比例以整数计算，避免大数乘法溢出。

未扣款试用不收补偿；确认撤权后释放首期预留，没有实际扣款就不虚构“已退回租金”。免费租约没有租金或补偿。旧计量租约仍按已确认服务与预留预算结算，不新增周期补偿。

最终必须满足：

```text
P = T + A + B + 本次已返还 + 已确认补偿 + 待裁定补偿
```

额度补差走既有服务交付、平台佣金、服务质量争议、收益沉淀和自动到账链路；不是额外的退租补偿。已交付服务的质量争议仍可从租用详情发起。退租补偿不再抽佣，确认后沉淀七天自动进入 Provider 平台余额，不提供手动转入或提现入口。

## 原车位撤权与最终用量

1. Router 在同一事务内冻结原租约身份、计费截止、已交付金额及不可变条款，停止续租，立即在本地封禁原 entitlement，排队撤销该 entitlement。不能按邮箱误撤同一用户的新租约。
2. Server 先持久化撤权，再等待该 entitlement 所有在途请求结束。试用请求和截止时刻附近的竞态请求也必须排空；只有截止前正式付费请求参与租金折算。
3. Server 从独立 SQLite 归档和执行账本构造最终回执，经 installation 签名 ACK 返回。回执绑定 termination、operation、Share、entitlement、邮箱、计费区间及归档起点；重放返回同一份不可变回执。
4. 尚有 pending／uncertain 用量时返回 `market_termination_pending`。Router 保留同一 edit 和操作指纹重试，不制造新 expectedRevision、不耗尽普通错误重试次数。Server 同样保留已执行操作的回放证据。
5. Router 验证回执后完成回收；结算在独立 savepoint 内提交。财务写入失败时保留回执和已验证撤权，车位可重新出租，原款项留在 `finance_pending`，由隔离恢复任务重试。缺 Share、描述符中没 grant、普通成功状态都不是最终用量凭证。

Server 拒绝删除仍有活跃市场授权，或最终退租 ACK 尚未被 Router 确认的 Share。最终 ACK 在发出前持久化，重启后可独立于 pending edit 列表重放；先保存本地标记清理，再移除 ACK outbox，避免网络丢失响应或进程崩溃留下永久删除门禁。物理数据丢失／手工删除数据库不能冒充成功回执；必须恢复原证据后继续处理，不允许人工点选责任来放款。

## 补偿问题处理

- 租客可选 Provider／平台问题，初始说明可留空，最多 2,000 UTF-8 字节；选择原因不是技术上认定责任。
- 确认受理起计 72 小时。Provider 可全部减免、部分减免，或正式回复并请求 Owner 裁决。部分减免或正式回复须至少三个字符的说明；剩余补偿继续冻结，正式回复不等于获得该款。
- 部分减免与首次正式回复开启同一轮七天 Owner 裁决期限；重复减免不延长期限。Owner 可以在剩余补偿范围内裁定 Provider 金额，并填写说明；不能追扣其他余额。
- Provider 72 小时未正式处理，或升级后 Owner 七天未处理，自动免除剩余补偿。截止时刻的并发操作由事务和版本号判定，不延用过期权限。
- 用户可主动关闭追讨：剩余冻结补偿归 Provider，本次追讨结束。当前 Share 实现不提供已自愿确认补偿的再次开启接口；已交付服务问题走独立服务争议，不混入未用租金。
- 弹窗引导双方到聊天室沟通；聊天、查看或刷新不算正式处理，不改变期限。站内通知按事项／阶段／角色去重，新增 Share 进度不发送多封邮件。

## 恢复、审计和前端一致性

`0107` 是增量迁移，不改写原账本。规则、报价／合约／周期条款、回执、处理事件与收入原始证据不可原地修改；金额的去向以封账流水为准。

恢复任务分别处理财务待核对、超时减免和到期补偿自动入账，使用持久化游标、有界扫描、逐项 savepoint，单笔异常不阻塞其他事项。资金对账覆盖原付款、最终消费、返还收款人、佣金、补偿归属及自动到账封账证据；异常只冻结相关买家／Provider／合约，孤立或未封账流水触发全局保护。

前端使用已有 Select 和共享弹窗。金额严格解析为十进制字符串；请求及选中事项按登录身份与车位隔离，关闭／换号取消加载。编辑期间不轮询覆盖输入，裁决冲突后须手动重新加载核对；退租请求结果未知时用同一请求重试。行按钮轮询只加载待办状态，不附带历史；打开详情后，处理历史独立分页，每页 50 条，加载更多不被自动刷新重置。

## 上线和验证边界

先升级 Router，再升级 Server，确认 Server SQLite 已 committed 且正常同步 `terminationArchiveSinceMs`。独立协商 `shareTerminationV1`；旧 Router 不接收新可选字段，旧 Server 或 JSON 权威 Server 不开放新报价条款。归档能力退失时不推测恢复、不绕过门禁。

新增 Rust 和前端单元回归覆盖迁移不改旧资金、原身份／回执重放、额度取高、试用零补偿、72 小时及七天超时、部分减免、自动到账幂等、安全解析和按角色显示的处理入口；Server 覆盖持久化请求修订、试用与竞态排空、USD 缺证据拒绝、删除保护及最终 ACK 丢失响应后的持久化重试。编译检查不等于执行测试，也不等于真实部署验收；生产发布仍需 CI 运行回归与受控的双端协议联调。本任务不运行截图或 UI 自动化。

# 导航栏通知中心与 Client 租用信息

## 范围与呈现

顶部铃铛统一命名为“通知中心”，按业务事实展示以下分类，不把外发邮件当作另一份通知：

| 分类 | 可见范围 | 事件来源 |
| --- | --- | --- |
| 钱包与交易 | 当前登录用户 | 既有充值、转账、C2C、收入及资金政策事件 |
| 租用服务 | 当前登录用户 | 既有服务暂停、恢复、终止及 Client 退租补偿事件 |
| Client 状态 | 事件发生时已验证的 Client owner | 新注册完成、确认离线、稳定恢复、离线移除 |
| Owner 告警 | 当前配置的 Router Owner | 既有告警引擎的触发、升级、恢复转换 |

普通管理员不因 `isAdmin` 获得 Router Owner 的系统告警。Owner 与管理员是独立权限；仅拥有 Owner 身份的账户仍可阅读、标读告警摘要，但不展示其无权进入的管理员监控详情入口，不扩大既有监控权限。Client 转移所有权后，旧通知不转给新 owner。同一账户兼任 Router Owner 和 Client owner 时，同一 Client 状态事件只显示个人通知，未持有该 Client 的 Owner 视角仍可见系统告警。

聊天保持独立的入口、未读计数与已读语义。通知中心不是“全站所有数据变更”日志；只接入上表明确的业务事件。后续新类型应在源业务事务中接入，而不是在浏览器拼接邮件投递历史。

前端提供单条已读、全部已读、刷新、游标分页、中英文、安全本地详情链接、键盘关闭与窄屏布局。关闭弹窗时，可见页面每 60 秒刷新未读数；打开时不自动覆盖正在阅读的历史。退出登录时卸载，切换账号时重建，旧请求不能填回新账号的列表。

## 存储与权限

- 主库迁移 97 新增 `user_notification_events`、`user_notification_reads`。不改写资金账本，不重置旧市场通知的已读或投递状态，不补发历史邮件。
- 市场事件仍由 `market_notification_outbox` 提供，复用既有 `read_at`。新站内事件与每用户已读独立保存；站内阅读不影响邮件、Telegram 或告警渠道的投递状态。
- `GET /v1/notifications` 每页最多 50 条，按时间及唯一 ID 稳定排序。游标、未读数及所有标读操作均在服务端按当前会话及 Owner 身份重新限制，响应为 `private, no-store`。
- `POST /v1/notifications/:id/read` 单条标读。全部标读使用 `id=all`，提交 `{through: readThrough}`，边界来自已加载快照、绑定用户及两个事件来源的插入高水位。加载后新到、同毫秒到达、回填旧时间的事件不会因时间排序被误标为已读。
- 新 Client 事件与状态变更同事务提交，按安装、事件种类及离线 episode 幂等。只保存标签，不复制可能含初始密码的注册快照。
- Owner 事件从 metrics 库告警转换按批镜像：先幂等写主库，再确认导出。中断允许重试但不重复建通知；提醒、外发重试和多渠道投递不重复建通知。不复制原始告警详情，仅保存简短标题、严重度和业务引用。站内镜像失败不阻断原有外发告警。
- 新非财务通知随主库保留；本次不引入自动清理资金事件或重写历史的机制。

## Client Market 行布局

已租用行首列保留分配状态、Client 在线状态和需要行动的试用／暂停／清理异常提示，不再显示正常周期时间或重复的“平台余额”链接。

展开行新增“当前租用”，显示到期结束／自动续费时间以及下次租用的试用额度，再展示既有使用历史。免费服务的期限也在详情内。展开箭头为可键盘操作的按钮；操作按钮不会误触发行展开。此调整不改变试用、收费、自动续费或退租规则。

## 验证与部署

后端覆盖角色／收件人隔离、跨来源分页、旧已读保留、批量已读边界、事务回滚、业务事件幂等、Owner 镜像重试与双身份去重、迁移 96→97 及重复启动。前端覆盖异常数据、本地链接、中英文、窄屏、键盘操作、切换账号的延迟响应与 Client 行详情。

部署时随新版正常运行 schema 迁移及告警库自动升级，不需手工更改资金数据。此前市场站内记录继续可见；新增个人 Client 通知从部署后的状态事件产生。保留期内尚未导出的既有 Owner 告警转换可进入站内历史，但不会因镜像重新发送邮件。

# DujiaoPay 充值单恢复

Router 只把 DujiaoPay 认证查单结果作为付款证据。收银台地址必须是官网当前文档给出的 `https://www.dujiaopay.com/checkout/{token}`；其他域名、路径及跳转参数均不展示。URL 不可用时保留已返回的网关订单 ID，并继续对账，不再产生一个不受追踪的新订单。正常的 `order.created`、`order.method_selected`、`order.confirming` 回调只用于绑定订单和触发查单，不证明付款，也不再误开人工核对单。

真实商户查单已观察到：`awaiting_payment` 和无付款的 `expired` 订单仍可能返回 `paid_source=chain`，同时没有交易号、付款时间、确认数或非零结算金额。因此仅在这些已知未付款阶段且其他付款字段均为空或为零时，把精确的 `chain` 视为支付渠道元数据；`merchant_claim`、其他未知来源及任何独立付款线索仍按付款证据隔离。此前仅由该字段误开的历史人工核对单，只有正常对账/Webhook 的脱敏网关观测摘要能逐条证明一直是同一无款 `chain` 快照、当前认证查单也是安全终态且本地无回执/账本/其他争议时，才自动结案并保留原核对记录；Owner 预览查询不能充当自动结案证据，不满足条件的继续由 Owner 核对。该规则不降低 `paid` 入账所需的链上回执校验。

买家在「账户 → 平台钱包 → 充值记录」可查看认证后的网关阶段及截止时间；仅网关仍为 `pending`、本地无付款或争议证据且未发起过取消时出现「取消支付」。所有付款入口先打开站内 `/wallet-checkout/` 页面，每次点击都重新认证查单、确认 `canPay` 后才跳往 DujiaoPay。Owner 在「设置 → Marketplace → 待核对充值单」先核实，再对同样符合条件的订单执行网关取消。Router 无法撤销用户已打开或保存的网关旧链接，仍须依赖网关终态和持续对账。

建单成功后由站内结账页独立进行一次新鲜查单；不可支付时页面保留并解释原因，不关闭新标签页。充值记录仅在认证确认可付时显示「继续支付」，否则显示「暂不可支付」及核实/停止操作，不把 `awaiting_payment` 标签误当作可支付能力。网关返回的收银台 URL 即使符合当前严格格式，站外托管路由仍可能返回 404；此时不能猜测或改写路径，也不能把本地订单视为付款成功。应暂停受影响渠道的新单，保留原单对账，并以真实商户受控浏览器和付款验收确认官方收银台恢复后再开放。站外 404 不能仅凭本地 mock、URL 语法或历史成功充值视为已修复。

买家可对尚未终结的订单选择「停止付款」：Router 立即隐藏站内收银台入口并记录操作（自迁移 `0069` 起只打标记、不清空已保存的收银台链接，订单保持可被取消和自动关闭），即使网关已经过期但本地仍在待核对也可操作；这**不是** DujiaoPay 撤单、退款或财务结案。已打开或保存的旧链接、已发出的转账仍可能生效，因此必须继续保留订单、回调、对账与迟到付款入账。认证查单确认网关为 `pending` 且本地无付款或争议证据时，另提供真正的「取消支付」并调用网关取消。新幂等键不复用已停止的订单，旧幂等键重放只返回无链接的原单。普通活动充值与最近 24 小时内已停止但网关未终态的充值各限每买家 3 笔；最近 24 小时内的待核对单另有限额，同时保留每小时/IP 建单限流，避免旧异常永久阻断新充值。限额窗口经过并不表示旧订单已结案；所有未终态的已停止订单仍持续认证查单。

部署时先备份数据库，再依次应用 `0065`（30 分钟自动核实）、`0066`（买家停止标记）、`0067`（脱敏网关观测）和 `0068`（买家查单进度），由同版后端提供新字段和接口后再发布前端。旧后端会拒绝比自身更新的迁移历史，不能在同一数据库上直接降级，也不能删除迁移记录或停止标记伪造回退；如需回退，先暂停充值，再部署识别现有表和停止标记的兼容版本。真实商户验收须覆盖停止后仍收到迟到付款，以及用户已有旧链接时不可将本地停止误认为网关撤单。

新建充值单持久化创建后 30 分钟的自动核实时间，历史订单不追溯赋值，避免升级时突然取消旧收银台。账户页显示倒计时及网关实际截止时间；最后五分钟提醒，倒计时归零只显示「核实中」，不能声称已关闭或立即催重复付款。后台按已有持久化队列主动查单：`awaiting_payment` 无法调用网关取消，等待网关终态；`pending` 在本地 30 分钟已到、且已知网关支付截止未晚于当前时间时，才沿与买家手动取消相同的认证查单、付款证据预检、网关取消、再次认证查单流程关闭。取消在数据库留下请求审计后至多发送一次；若取消响应丢失或网关暂未确认，后台继续认证查单而不重复 POST。若网关尚可付款、查单失败、进入 `confirming`/`paid` 或出现付款证据，则不因本地计时器强制关闭。买家可限频请求重新核实；只有认证确认的 `expired`/`cancelled` 才显示重新发起充值入口。待核对单不再占三个活动收银台名额，但仍受最近 24 小时内十笔待核对上限和每小时建单限流保护；同渠道同金额的核实中／待核对单不再被新幂等键复用，前端会提示这是一笔独立付款并要求确认。同一幂等键始终指向原单，建单结果不明时不能换键盲目重试。

旧版本把 `order.created` 误判为未知事件的订单，仅在网关认证查询确认 `expired`/`canceled`，且没有付款事件、其他争议、充值回执或账本分录时，后台才会在同一数据库事务内关闭旧核对单并释放待处理名额。网关结算金额必须是严格的十进制零值；允许网关使用超过两位小数的零值，但非零或无法识别的值仍阻断释放。已付款、身份或金额不符、未知网关状态一律不得自动释放；已付款仍须通过原有严格回执和账本校验。

曾出现「网关已过期但带付款证据」的历史核对单不得自动关闭；如果后续认证查单已是无付款证据的安全终态，Owner 仍须在商户后台独立核对并提供可追溯的核验编号、勾选人工确认，才能在同一事务中结案。若网关后来明确报告 `paid`，则仅在付款身份、金额、链上回执与唯一性均通过严格校验，且不存在其他争议时，系统才在同一事务中解除这类单一兼容核对单并入账一次。原有事件、核对单与脱敏决策回执永久保留。当前查单仍带交易号、付款时间、确认数、非零结算金额等证据，或存在回执、账本、其他争议时，仍禁止按未付款结案；用户的「核实付款」只唤醒查单，不能自行清除核对单。

Owner 可在「设置 → Marketplace → 待核对充值单」逐笔处理未自动恢复的订单。若订单没有保存网关订单 ID，先在 DujiaoPay 商户后台按 Router 商户订单号核对，再填入对应网关订单 ID。先点「向网关核实」进行不改变订单或账务的预检，系统会留下脱敏网关观测；界面会分别列出网关付款字段、本地回执/账本、事件和审核单等阻断原因。普通可释放订单经确认弹窗提交；若历史订单同时存在无具体原因的 `topup_verification_failed`，还须由 Owner 在商户后台核对并填写可追溯的商户订单 ID 或核验工单号，勾选人工确认。编号本身不是付款证明，Owner 必须实际检查商户记录中没有付款或未结争议。提交会重新认证查单、复核订单身份、金额与版本，在同一事务内关闭符合条件的审核单、变更状态并写入操作者、核验编号及脱敏网关证据摘要。预检成功不保证稍后的提交也成功。

待核对订单、财务异常和每单的脱敏网关观测均可分页加载，超过首屏的记录不会被静默截断。网关返回付款证据字段但类型异常时，查单会失败并保持原有冻结状态，不会将格式异常解释为「无付款」。

「关闭核对」只退出界面，不改变订单。「关闭未支付订单」不删除订单、回调、回执或账本；安全终态退出待处理数量。系统对所有仍未终态的订单持续低频认证查单，安全终态的旧订单仅在有限窗口或新通知时复查。DujiaoPay 当前文档提供签名 `POST /v1/orders/{id}/cancel`，但仅允许网关 `pending`；未选择链/币的 `awaiting_payment` 不能取消。Router 的本地 `pending` 同时覆盖这两个网关状态，因此按钮必须以认证查单和本地付款证据检查为准。取消请求结果不作付款或终态证据：请求超时、409 和成功响应之后都重新认证查单；再次请求时若已认证得到安全终态，直接完成本地关闭，不重复向网关发取消请求。只有网关确认 `canceled`/`expired` 且无付款、争议、回执或账本证据时，普通充值单才退出待处理名额。历史上仅因普通进度事件误冻结的核对单，按现有安全对账规则在确认终态后释放；仍需人工商户核验的异常单继续冻结，须另走核对流程。取消不退款，已发出但尚未被网关识别的链上转账可能成为未匹配资金，必须继续核对收款账户与链上流水；不能仅靠订单终态轮询声称已经处理所有迟到资金。有付款证据、异常事件或无法解释的身份冲突时保持冻结，不得仅通过关闭 case 或改数据库绕过。

如果取消请求已有审计记录而网关长期保持 `pending`，买家和 Owner 都不能重新发送可能非幂等的取消 POST，也不能重新开放该收银台。Owner 应对照 DujiaoPay 商户记录联系网关核实，等待可认证的安全终态；在此之前订单继续对账和隔离，不能手改状态释放。

发起网关取消后，Router 立即移除该单的站内收银台链接；后续查单也不得把它写回。新幂等键不能按同渠道同金额复用这笔已发起取消的单，但原幂等键重放仍只返回原单，避免创建结果不明时产生重复订单。

部署前须用真实商户在影子模式验证：建单返回的地址确为上述官方收银台、跳转可用；正常进度回调不冻结订单；`awaiting_payment` 不出现网关取消按钮，也不会被 30 分钟本地计时器伪关闭；`pending` 的自动与手动取消、网关延后截止、重复取消、409、超时回查、回调乱序、密钥轮换与过期释放名额；真实链上到账只入账一次；网关错单、退款事件和重复回调均保持资金安全。不得把本地 mock 或只读官网文档当作真实商户验收，也不得为验证而替用户发起真实付款。

自迁移 `0069` 起：建单请求体冻结，重放逐字节相同；同一请求两次被网关校验拒绝且订单列表中查无该商户单号时，订单以 `cancelled`（`local_close_reason = never_created`）结案；已停止订单的重放若首次绑定出一张 `pending` 网关单，立即发起一次取消。签名回调立即返回 2xx，入账与状态推进统一在对账循环的认证查单中完成，查单完成后此前的待处理事件自动结束，不再阻断恢复操作。

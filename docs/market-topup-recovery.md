# DujiaoPay 充值单恢复

Router 只把 DujiaoPay 认证查单结果作为付款证据。收银台地址必须是官网当前文档给出的 `https://www.dujiaopay.com/checkout/{token}`；其他域名、路径及跳转参数均不展示。URL 不可用时保留已返回的网关订单 ID，并继续对账，不再产生一个不受追踪的新订单。正常的 `order.created`、`order.method_selected`、`order.confirming` 回调只用于绑定订单和触发查单，不证明付款，也不再误开人工核对单。

买家在「账户 → 平台钱包 → 充值记录」可查看认证后的网关阶段及截止时间；仅网关仍为 `pending`、本地无付款或争议证据时出现「取消支付」。历史订单的「继续支付」链接也只在网关确认仍可付款时展示。Owner 在「设置 → Marketplace → 待核对充值单」先核实，再对同样符合条件的订单执行网关取消。

网关仍为 `awaiting_payment` 且认证查单、本地付款证据均安全时，买家可选择「放弃本次充值」。这是独立的买家意图标记，不会把 DujiaoPay 订单标为取消，也不执行选链或网关取消。Router 不再返回该订单的收银台链接；已打开或保存的旧链接仍可能付款，必须继续保留网关订单、回调、对账与迟到付款入账。新幂等键不复用已放弃订单，旧幂等键重放只返回无链接的原单。普通活动充值与已放弃但网关未终态的充值各限每买家 3 笔，另保留原有待核对上限和每小时/IP 建单限流；超过放弃单上限只阻止新建，不阻止买家放弃当前单。网关认证确认安全终态后才释放放弃单名额。超过常规 90 天对账窗口仍未终态的放弃单继续低频认证查单，不可静默从渠道未结统计中消失。

部署时先备份数据库，再依次应用 `0065`（30 分钟自动核实）与 `0066`（买家放弃标记），由同版后端提供新字段和接口后再发布前端。回退应用程序时保留迁移及放弃标记，不能把已放弃订单重新作为可付款链接返回；因此若必须回退到不识别 `buyer_abandoned_at` 的旧后端，应先停止对外充值，待兼容版本部署后才重新开放。真实商户验收须覆盖放弃后仍收到迟到付款，以及用户已有旧链接时不可将本地放弃误认为网关撤单。

新建充值单持久化创建后 30 分钟的自动核实时间，历史订单不追溯赋值，避免升级时突然取消旧收银台。账户页显示倒计时及网关实际截止时间；最后五分钟提醒，倒计时归零只显示「核实中」，不能声称已关闭或立即催重复付款。后台按已有持久化队列主动查单：`awaiting_payment` 无法调用网关取消，等待网关终态；`pending` 在本地 30 分钟已到、且已知网关支付截止未晚于当前时间时，才沿与买家手动取消相同的认证查单、付款证据预检、网关取消、再次认证查单流程关闭。自动取消在数据库留下请求审计后至多发送一次；若取消响应丢失或网关暂未确认，后台继续认证查单而不静默重复 POST。若网关尚可付款、查单失败、进入 `confirming`/`paid` 或出现付款证据，则不因本地计时器强制关闭。买家可限频请求重新核实；只有认证确认的 `expired`/`cancelled` 才显示重新发起充值入口。待核对单不再占三个活动收银台名额，但仍受独立的十笔待核对上限和每小时建单限流保护；同渠道同金额的待核对单仍保持幂等复用，避免无提示重复付款。

旧版本把 `order.created` 误判为未知事件的订单，仅在网关认证查询确认 `expired`/`canceled`，且没有付款事件、其他争议、充值回执或账本分录时，后台才会在同一数据库事务内关闭旧核对单并释放待处理名额。网关结算金额必须是严格的十进制零值；允许网关使用超过两位小数的零值，但非零或无法识别的值仍阻断释放。已付款、身份或金额不符、未知网关状态一律不得自动释放；已付款仍须通过原有严格回执和账本校验。

曾出现「网关已过期但带付款证据」的历史核对单不得自动关闭；如果后续认证查单已是无付款证据的安全终态，Owner 仍须在商户后台独立核对并提供可追溯的核验编号、勾选人工确认，才能在同一事务中结案。原有事件、核对单与脱敏决策回执永久保留。当前查单仍带交易号、付款时间、确认数、非零结算金额等证据，或存在回执、账本、其他争议时，仍禁止结案；用户的「重新核实」只唤醒查单，不能清除核对单。

Owner 可在「设置 → Marketplace → 待核对充值单」逐笔处理未自动恢复的订单。若订单没有保存网关订单 ID，先在 DujiaoPay 商户后台按 Router 商户订单号核对，再填入对应网关订单 ID。先点「向网关核实」进行不写库预检；界面会分别列出网关付款字段、本地回执/账本、事件和审核单等阻断原因。普通可释放订单经确认弹窗提交；若历史订单同时存在无具体原因的 `topup_verification_failed`，还须由 Owner 在商户后台核对并填写可追溯的商户订单 ID 或核验工单号，勾选人工确认。编号本身不是付款证明，Owner 必须实际检查商户记录中没有付款或未结争议。提交会重新认证查单、复核订单身份、金额与版本，在同一事务内关闭符合条件的审核单、变更状态并写入操作者、核验编号及脱敏网关证据摘要。预检成功不保证稍后的提交也成功。

待核对订单和财务异常均可分页加载，超过首屏的记录不会被静默截断。网关返回付款证据字段但类型异常时，查单会失败并保持原有冻结状态，不会将格式异常解释为「无付款」。

「关闭核对」只退出界面，不改变订单。「关闭未支付订单」不删除订单、回调、回执或账本；安全终态退出待处理数量。系统会在订单创建后 90 天内主动对账，超过 90 天仍按既有认证流程处理迟到付款通知。DujiaoPay 当前文档提供签名 `POST /v1/orders/{id}/cancel`，但仅允许网关 `pending`；未选择链/币的 `awaiting_payment` 不能取消。Router 的本地 `pending` 同时覆盖这两个网关状态，因此按钮必须以认证查单和本地付款证据检查为准。取消请求结果不作付款或终态证据：请求超时、409 和成功响应之后都重新认证查单；再次请求时若已认证得到安全终态，直接完成本地关闭，不重复向网关发取消请求。只有网关确认 `canceled`/`expired` 且无付款、争议、回执或账本证据时，普通充值单才退出待处理名额。历史上仅因普通进度事件误冻结的核对单，按现有安全对账规则在确认终态后释放；仍需人工商户核验的异常单继续冻结，须另走核对流程。取消不退款，已发出但尚未被网关识别的链上转账可能成为未匹配资金，必须继续核对收款账户与链上流水；不能仅靠订单终态轮询声称已经处理所有迟到资金。有付款证据、异常事件或无法解释的身份冲突时保持冻结，不得仅通过关闭 case 或改数据库绕过。

部署前须用真实商户在影子模式验证：建单返回的地址确为上述官方收银台、跳转可用；正常进度回调不冻结订单；`awaiting_payment` 不出现网关取消按钮，也不会被 30 分钟本地计时器伪关闭；`pending` 的自动与手动取消、网关延后截止、重复取消、409、超时回查、回调乱序、密钥轮换与过期释放名额；真实链上到账只入账一次；网关错单、退款事件和重复回调均保持资金安全。不得把本地 mock 或只读官网文档当作真实商户验收，也不得为验证而替用户发起真实付款。

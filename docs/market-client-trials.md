# Client 试用与市场首期余额

## 配置

- Router owner 在「设置 → 市场 → 平台钱包 → 市场试用规则」中设置默认 Client 试用小时数。默认 12，允许 0–720 的整数，0 表示不试用；独立版本与审计，不修改充值维护费策略。
- Host owner 在添加 Host、修改报价时可填写自定义试用；留空继承 Router 默认值，明确填写 0 则不继承。租用者不能修改试用额度。
- Host 导入／导出的 JSON `trialHours`、文本可选第八列保留此覆盖值，包含 0。旧文件未填写时继承默认。
- 修改默认值仅影响新报价；修改 Host 覆盖值会增加报价版本，已有报价或合同不会被重写。保留中的报价或锁定的 Host 不可变更条款。
- 同一用户在同一 Provider、同一 Host／Share 上的已消费试用时长不会因释放重租而重置。报价同时冻结总额度及剩余额度，避免重复扣减历史用量。

## 首期余额

所有付费 Client／Share 在提交订单时，必须具备完整首期价款的可用余额，包括有试用的订单。已冻结资金不可重复使用，已到期的其他合同义务优先；批量下单须满足合计价款。报价后余额变化会导致提交失败，事务不留下部分合同或部署任务。

试用期间不扣款、不冻结资金；实际可用的服务时间才消耗试用。试用为 0 时，按正常付费开通流程冻结首期价款，开通确认后扣款。真正免费商品与 Provider 自用不受付费余额门槛影响。Share 使用同一试用策略中的独立默认时长与 Token 数，不继承 Client 时长，见 [市场试用规则](market-trial-rules.md)。

## 首次扣款失败

试用耗尽时若无法开始首个付费周期，钱包对账立即将合同设为 `ending` 并派发回收，不保留资源等待充值。正常调度间隔为 5 秒，远程清理耗时另计；不是试用结束后再等待 7 天。

Client 必须停止旧进程、清除租用数据和身份绑定，确认完成后才将 Host 变回可出租。清理失败或结果不明继续隔离、按已有机制重试，不能提前把脏 Host 交给下一位用户。Share 则在确认撤权后释放座位。后续补款不会撤销正在进行的回收；用户需要重新下单。

已有从未转付费、试用耗尽的暂停租用也会被回收。财务隔离及未确认外部状态的保护仍优先。已经付费后的续费／预算不足保留原暂停策略，不改变已付款服务期限。

迁移 92 只增加配置及报价冻结字段，不修改历史钱包、已消费试用或合同价款。上线前按常规升级流程备份数据库。

# Router 升级进度与中断

2026-11-27。已接入实现；验证范围为 Rust 编译、TypeScript 类型检查、静态契约检查及源码 review，不包含部署、启动服务、运行测试或 UI 测试。

## 界面与交互

Operations → 服务中的升级在「版本」卡片下方显示独立浅色面板，取消旧的深色日志弹窗。面板总高在窄屏为 320px、640px 起为 400px；顶部状态和底部操作保留在面板内，中间日志独立滚动。只有下载阶段显示实际下载量和已知的下载百分比，不将阶段序号伪装成整体完成比例。用户向上阅读时暂停自动滚动，可点击「回到最新」。

页面挂载、刷新及重新可见时查询最近任务。运行中始终显示；结束后保留结果和日志，并出现「关闭」。浏览器仅在 `cc_switch_router_upgrade_dismissed_v1:<accountId>` 中记录该账号关闭的任务 ID，不保存日志或凭据。其他账号和新任务不受影响，同账号标签页同步关闭记录。最近任务在下一次升级开始时被替换，不提供无限增长的历史列表。

升级完成不强制刷新页面；版本卡片重新读取实际运行信息。前端资源更新继续使用现有 `UiUpdateNotice` 提示。用户刷新后从后端恢复未关闭的升级窗口。服务完全不可达时无法重新加载网页，已打开页面保留进度并重连，服务恢复后可再次刷新。

## 状态与持久化

`src/admin/upgrade_task.rs` 保存任务状态和有序日志；`src/admin/upgrade.rs` 执行下载、校验、安装、重启和恢复。状态为：

| 状态 | 意义 | 可关闭 |
| --- | --- | --- |
| `running` | 准备、下载、校验、计算指纹或安装 | 否 |
| `cancelling` | 已接受中断，正在停止并清理 | 否 |
| `restarting` | 等待目标进程接管或确认就绪 | 否 |
| `success` | 新实例已运行目标程序且服务就绪 | 是 |
| `failed` | 升级执行、清理或持久化失败 | 是 |
| `cancelled` | 中断结束且暂存文件已清理 | 是 |
| `interrupted` | 原进程意外停止，未完成升级 | 是 |

阶段独立为 `preparing/downloading/validating/hashing/installing/restarting/verifying/complete`；后端计算 `canCancel`，前端不得仅凭阶段名称自行授权。`binaryReplaced` 区分替换前失败和替换后恢复失败，淘汰“一切失败都未替换二进制”的文案。

最近任务写入 `data_dir/upgrade/current.json`，目录为 `0700`、新文件为 `0600`。临时文件写入、文件 fsync、同目录 rename、目录 fsync 后才发布新快照。任务和日志同一快照提交，避免状态与日志序号不一致。日志保留最近 1000 条，每条消息最多 1024 字符；journal 读取和写入均限制为 8 MiB。下载进度至多每秒记录一次，阶段切换和结果立即落盘。日志使用 `seq`，快照使用 `revision`。落盘失败时内存快照的 `revision` 仍会递增并被浏览器看到，因此新进程加载 journal 时把 `revision` 抬到不低于当前毫秒时间戳，保证恢复后发布的状态不会被已打开页面当作旧状态丢弃。

落盘失败时停止替换前的执行，并禁止新升级、重启和回滚，保留实时故障提示；不得因为任务“失败”就绕过持久化故障。损坏或未知版本 journal 只隔离维护动作，不阻塞 Router 为已有用户提供服务。排查服务日志、保留故障文件并恢复正确状态后重启，重新核对 journal。不要通过删除业务数据库或更换 Client 身份处理此问题。

## 中断边界

准备、下载、程序自检、`build-info`、`check-db` 和哈希计算可中断；数据库检查继续使用既有兼容检查，不执行业务 schema migration。下载的请求等待、流读取和文件写入监听取消信号；检查子进程取消或超时时显式 kill 并 wait，`kill_on_drop` 作为兜底；哈希分块读取并监听取消信号。

接受取消和进入 `installing` 使用同一任务锁，均先持久化再发布。取消先成功则禁止进入安装；安装先成功则返回 `409 UPGRADE_NOT_CANCELLABLE`。整个备份、替换和重启交接阶段不可中断。只有停止完成并清理暂存文件后才写 `cancelled`，清理失败写 `failed` 并保留具体诊断。

中断请求与新任务的发布还通过 registry 锁串行化，旧任务的重复取消不能覆盖新任务 journal。重复取消同一已中断任务返回现状，不重复改写。升级、重启、回滚共享服务操作锁，任一任务进行中均拒绝冲突操作；安排重启后继续保留本进程的维护锁定。

“立即中断”指请求送达并被接受后立即触发停止，不等待下载或校验自身的超时；网络不可达、内核 I/O 及进程回收不具备毫秒级完成保证。离开页面、关闭订阅及前端请求超时不会取消服务端任务。

## 安装与重启确认

候选程序的 `build-info` 必须声明 `upgradeProtocolVersion=1`，未知或旧协议在替换前拒绝。下载仍使用 GitHub `latest` 的 AMD64 binary 和既有 180 秒下载期限，目标 SHA-256 用于运行程序核对，不是新增的发布方 checksum 校验。

旧程序先复制到同目录暂存备份，文件 fsync 后原子覆盖 `.bak` 并同步目录，再原子覆盖安装目标；不再先将安装路径移走。大文件备份放入 blocking worker。替换事实与重启交接先写 journal，再创建既有 systemd/nohup 重启子进程；成功创建子进程只表示 `restarting`。

新实例启动后读取 journal，以 `/proc/self/exe` 的 SHA-256 核对实际运行程序，而非只检查已经被替换的安装路径。还须满足实例 ID 已变化；HTTP 和 SSH 监听均绑定并启动之后，由本进程无代理 loopback 探测确认：HTTP 健康检查报告数据库可用，SSH 端口返回 `SSH-` 标识（仅端口已绑定不算，内核 backlog 也会完成 TCP 握手），再持久化 `success`。相同 binary 的升级同样需要实例变化。过去已经结束的任务不会因一次普通启动被改写成成功。

若原进程安排重启后仍存活 300 秒，则由该原进程记录明确的重启失败；原进程已经消失时，浏览器不能仅凭连接超时推断成功或失败。新进程最多等待 300 秒确认就绪，超时则写入 `failed`（保留 `binaryReplaced`，错误中说明未就绪的是 HTTP/数据库还是 SSH），从而解除服务操作锁，管理员可直接在页面重启或回滚，无需登录服务器；等待期间页面提示检查服务日志并继续重连。替换后安排重启失败保留 `.bak` 和实际替换状态，由管理员查看诊断后选择重启或回滚，不擅自回滚业务数据库。

## 浏览器协议

所有接口要求管理员会话；状态响应禁止缓存。

| 接口 | 请求／响应 |
| --- | --- |
| `POST /v1/admin/upgrade` | 创建任务，返回 `{taskId,task}` |
| `GET /v1/admin/upgrade/status?taskId=...` | 返回 `{task}`；不传 ID 发现最近任务，无任务为 `null`，旧 ID 为 404 |
| `POST /v1/admin/upgrade/cancel` | 请求 `{taskId}`；返回已接受的任务状态，或明确冲突 |
| `GET /v1/admin/upgrade/stream?taskId=...&afterSeq=...` | SSE `log/state/done`；日志 ID 为 `<taskId>:<seq>`，支持同任务的 `Last-Event-ID` |

SSE 在读取快照前订阅唤醒信号，每次从 journal 内存快照按序补发。broadcast 只作唤醒，不作为日志权威，因此订阅时序或接收 lag 不丢失保留范围内的日志。`state` 不重复携带日志正文。前端合并轮询与 SSE 时按任务、revision 和 seq 去重，不让迟到的旧查询回退结果或覆盖下一轮任务。凭据轮换后重新读取会话 token 建立订阅；登录上下文变化时取消旧请求并丢弃旧回调。

进入重启交接时发送最后的 state 并结束旧 SSE，浏览器改为轮询状态，避免该流拖住旧进程的优雅 HTTP drain；这不是任务终态，也不会解锁服务操作。新进程仍在验证时可重新订阅，确认后按正常终态处理。

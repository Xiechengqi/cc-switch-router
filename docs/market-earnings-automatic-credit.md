# 供应商收益自动到账与封闭余额流转

本文是当前收益结算契约，替代平台钱包旧规划中的外部提现、提现地址和手动收益转入流程。

## 资金规则

- 只有买家已扣款且服务已履约的收入才能生成收益，仍按冻结的周期费率扣除平台服务费。
- 沉淀截止时间仍为 `max(买家扣款时间, 履约时间) + 7 天`。没有提前放款、二次服务费或充值维护费。
- 完成沉淀的净收益由后台自动、1:1 计入同一用户的平台钱包，无需登录页面、报价、验证码或手动确认。
- 平台钱包余额可直接支付两个市场的服务、通过邮箱转给其他已验证用户，或在 C2C 中出售。C2C 仍受 Owner 开关、余额准入门槛、在线状态、库存冻结、线下收款确认和放行验证码约束，不会自动把用户设为卖方。
- Router 不提供外部提现、提现地址管理或余额现金退款。C2C 的线下付款由交易双方承担，Router 只转移卖方已冻结的真实余额，不承担付款或收益保证。

## 自动结算与安全边界

独立后台任务每约 30 秒先释放到期收益，再自动入账；不等待充值网关的网络请求。每轮最多处理 200 笔，积压会持续分批处理。

每笔入账都在 IMMEDIATE 事务及独立 savepoint 中完成：检查用户与 Provider 身份、沉淀时间、收益冻结、合同及账户财务范围，再核验原始服务费和收益处置证据。复式 journal 同时减少 `provider_available` 负债、增加 `wallet_available` 负债，更新同一用户钱包与 lot 的已入账数量；任一步失败全部回滚。

原 `market_earning_*conversion*` 表名作为历史账本格式保留。自动结算的冻结证据在同一事务内生成并消费，`automatic = 1`、审计原因 `automatic_settlement`，不是需要用户确认的报价。金额使用原有 USD 整数记账单位，不丢弃不足一美分的尾数；重复循环、并发或进程重启不得重复入账。

用户停用、邮箱未验证、身份冲突、争议冻结或账务不变量异常都会阻止相关款项进入可转出的余额。扫描游标持久化轮转，冻结账户或单个异常合同不会饿死其他收益，解除原因后自动重试。新充值/新订单暂停及旧手动转入暂停不拦截已有收入结算。完整异常证据仍由财务审计和冻结处理流程管理。

自动微批次不逐笔发送强制邮件；用户通过收入明细、钱包流水及导航栏余额查看到账。可见页面每 15 秒刷新收入数据，导航余额沿用统一轮询；时间到期本身不能让浏览器宣称余额已经到账。

## 页面与 API

账户的「供应商收入」只保留沉淀中、累计到账、冻结中的金额，以及收益和服务费明细。提供查看钱包、C2C 出售、邮箱转账入口。两个市场余额不足时不再显示手动「转入余额」。

- `GET /v1/market-provider-finance/me`、`earnings`、`holds` 保留只读收入数据，不再返回提现能力或地址。
- 收益到账历史 `GET .../wallet-conversions` 及单条读取继续保留，便于审计。
- 原提现申请、审批、付款登记、地址和地址验证码接口统一返回 `410 PROVIDER_PAYOUTS_RETIRED`。
- 原手动收益报价和确认写接口返回 `410 MANUAL_EARNING_CONVERSIONS_RETIRED`。
- 付费 Share/Host 发布只要求有效供应商身份，不再依赖外部提现地址及其 24 小时冷静期。
- Owner 设置不再提供提现处理、新提现暂停或手动收益转入暂停。

迁移 79 增加自动入账标记及轮转游标，并在数据库层拒绝新提现、地址及地址验证码写入。既有外部付款凭证、处置数量和历史 journal 仅用于审计，不删除、不伪造已付款，也不擅自解冻不确定的历史资金。

## 验证范围

回归覆盖 Share/Host 收益、七天边界、服务费净额、尾数精度、幂等、并发处置、单笔失败回滚及重试、冻结和停用隔离、公平扫描、无手动报价频率限制，以及自动到账后 C2C 放行和邮箱验证码转账。迁移测试验证旧余额及历史付款资料不被改写，旧客户端无法新增外部出款义务。
